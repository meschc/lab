# Жатва

Жатва копит материал текущего проекта в `~/Проекты/Кейсы/<проект>/`: `case-study.md` (сырьё и сведённый текст), `case-study.html` (статья), `media/` (скриншоты и видео). Фоновый сбор идёт хуками сам; этот скилл — ручное управление.

Все действия — через CLI, из папки проекта (текущий cwd сессии):

```
sh .zhatva/collector/bin/zhatva.sh <подкоманда>
```

## Какую подкоманду выбрать

| Что сказал пользователь | Подкоманда |
|---|---|
| «жатва», «запусти жатву», «жатва статус», «что собрала» | `status` |
| «покажи кейс», «жатва, покажи решения» | `show` или `show <секция>` |
| «включи жатву», «веди кейс» | `on` |
| «выключи жатву», «не собирай тут» | `off` |
| «жатва, запиши…», «зафиксируй момент» | `log "<заметка>"` |
| «подтяни прошлые сессии», «собери задним числом» | `backfill` |

Если просьба неоднозначна — начни со `status`.

## Правила

- `status` показывай как есть, кратко, без пересказа всего документа.
- `log` без текста от пользователя: сам сформулируй одно-два предложения о том, что только что произошло в разговоре (проблема → как решилась), и передай их в `log`. Секреты в заметку не вставляй.
- `backfill` долгий, прогресс идёт в stderr, повторный запуск безопасен. Предлагай только для проекта, который начали вести задним числом.
- Проект не отслеживается — скажи об этом и предложи `on`; не включай без ответа пользователя.
- Сессии в облаке (claude.ai/code) хуки не видят: если пользователь работал там, предложи перенести сессию локально (`claude --teleport <id>`) и потом сделать `backfill`.
